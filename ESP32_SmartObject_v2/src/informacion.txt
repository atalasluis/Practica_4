Publicación basada en eventos

    evento ocurre → publicar

    Justificación académica:
    El Shadow se utiliza para representar el estado actual del dispositivo y no como mecanismo de almacenamiento histórico o streaming continuo, reduciendo tráfico MQTT y costos cloud.

Base de datos:

| Campo          | Tipo    | Uso                  |
| -------------- | ------- | -------------------- |
| eventId        | String  | ID único             |
| timestamp      | String  | fecha/hora           |
| speed          | Number  | velocidad detectada  |
| exceeded       | Boolean | excedió límite       |
| speedLimit     | Number  | límite vigente       |
| barrierClosed  | Boolean | barrera activada     |
| alarmActivated | Boolean | alarma activada      |
| deviceId       | String  | identificación ESP32 |
| hour           | Number  | análisis horario     |
| day            | String  | análisis semanal     |


¿Por qué guardar "hour"?

    Porque luego puedes hacer:

    * horas con más infracciones
    * histogramas
    * frecuencia temporal

    SIN recalcular siempre.

¿Por qué guardar "day"?

    Porque luego podrás:

    * comparar días
    * patrones semanales
    * fines de semana.

¿Cuántas tablas usar?
    Recomendación para Free Tier:
    SOLO UNA TABLA

    SpeedEvents

¿Por qué?

    Porque:

        simplifica arquitectura
        simplifica consultas
        reduce complejidad
        suficiente para la práctica.

Qué puedes analizar con UNA tabla

    Fácilmente:

        horas con más infracciones
        velocidad promedio
        frecuencia de exceso
        cantidad de alarmas
        cantidad de cierres barrera
        efectividad sistema
        comparación antes/después

¿Qué es systemStatus?

    systemStatus representa:

        el estado operativo general del dispositivo

    Recomiendo algo SIMPLE:

        | Valor  | Uso              |
        | ------ | ---------------- |
        | online | normal           |
        | alarm  | exceso detectado |
        | error  | fallo sensor     |
